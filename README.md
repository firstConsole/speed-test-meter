# speed-test-meter

Консольный замерятель скорости интернета. Последовательно скачивает один и тот
же адрес заданное число раз, дожидаясь каждого ответа целиком, и печатает
среднее время запроса, объём скачанных данных и скорость.

Ни одной runtime-зависимости: загрузка выполняется стандартным `urllib`.
Достаточно Python 3.10 или новее.

## Быстрый старт

### Через Poetry

```bash
git clone https://github.com/firstConsole/speed-test-meter.git
cd speed-test-meter
poetry install
poetry run speedmeter https://speed.cloudflare.com/__down?bytes=10000000
```

### Без установки

Runtime-зависимостей нет, так что хватит любого Python 3.10+, даже системного.
Пакет лежит в `src/`, поэтому каталог нужно указать явно:

```bash
git clone https://github.com/firstConsole/speed-test-meter.git
cd speed-test-meter
PYTHONPATH=src python3 -m speedmeter https://speed.cloudflare.com/__down?bytes=10000000
```

В PowerShell — `$env:PYTHONPATH="src"; python -m speedmeter ...`

В этом режиме `--version` покажет `0.0.0+unknown`: номер берётся из метаданных
установленного дистрибутива, а их при запуске прямо из исходников нет. На сам
замер это не влияет.

Адрес нужен тяжёлый — большая картинка или тестовый файл. На маленьком файле
соединение не успевает разогнаться, и замер покажет не скорость канала, а
накладные расходы на установку соединения.

## Параметры

| Флаг | По умолчанию | Назначение |
|---|---|---|
| `url` | — | Адрес для скачивания, `http://` или `https://` |
| `-n`, `--attempts` | `10` | Сколько последовательных запросов сделать |
| `-t`, `--timeout` | `30` | Таймаут сокета на попытку, в секундах |
| `--warmup` | `0` | Сколько запросов сделать и выбросить до начала замера |
| `--json` | выкл. | Вывести отчёт в JSON вместо текста |
| `--quiet` | выкл. | Не печатать прогресс |
| `--version` | — | Показать версию |

### Зачем `--warmup`

Первый запрос к хосту оплачивает разрешение DNS и, поверх HTTPS,
TLS-рукопожатие. К пропускной способности канала это отношения не имеет, но в
замер попадает. Эффект хорошо виден даже на локальном сервере, где сети нет
вовсе: первая попытка `362 MB/s`, все последующие — выше `2200 MB/s`.

По умолчанию прогрев выключен, то есть поведение «из коробки» — ровно десять
запросов, как в задании.

```json
  "units": {
    "bytes_per_megabyte": 1000000,
    "bits_per_megabit": 1000000
  }

```

Три свойства схемы стоит отметить.

Числа **не округляются**: вывод предназначен для вычислений, а округление
необратимо. Кому нужны два знака — округлит сам.

Несуществующие величины — `null`, а не ноль. Если ни одна попытка не удалась,
`megabytes_per_second` будет `null`: потребитель, сравнивающий `null` с
порогом, получит ошибку, а сравнивающий `0.0` — уверенный неверный ответ. При
этом `total_bytes` остаётся нулём, потому что «ничего не скачано» — это факт, а
не отсутствие данных.

Блок `units` описывает основание единиц прямо в документе, чтобы потребителю не
пришлось гадать между `10^6` и `2^20`.

## Коды возврата

| Код | Значение |
|---|---|
| `0` | Скорость измерена |
| `1` | Все попытки провалились, измерять нечего |
| `2` | Команда использована неверно: битый адрес или аргумент |

Единица и двойка разделены намеренно. Для мониторинга «канал лёг» и «опечатка в
URL» — разные ответы, и одним ненулевым кодом их смешивать нельзя.

## Как считается скорость

### Сумма байт делится на сумму времени

Не среднее из десяти поточечных скоростей. Разница не косметическая: усреднение
скоростей даёт каждой попытке одинаковый вес независимо от того, сколько данных
она перенесла. На прогоне, где одна попытка скачала 10 МБ за 2 с, а другая
1 КБ за 1 мс, честный агрегат даёт **4.998 МБ/с**, а среднее из скоростей —
**3.000 МБ/с**. Расхождение в 40% на ровном месте.

### Единицы

В задании написано «мб/с», и это двусмысленно: мегабайт по СИ — это `10^6`
байт, а мебибайт по МЭК — `2^20`, они различаются на 4.9%. Программа считает по
СИ и печатает обе величины, МБ/с и Мбит/с, с одним основанием — чтобы их можно
было сравнивать между собой и с цифрой в тарифе провайдера. Основание указано в
самом выводе.

### Разброс

Среднего мало. Когда все попытки скачивают один и тот же файл, агрегатная
скорость оказывается ровно гармоническим средним поточечных, а значит уже
проседает на нестабильной связи — и **смешивает «медленно» с «нестабильно»**.
Два прогона с одинаковым заголовком `4.3389 МБ/с`:

| | Заголовок | Мин. | Макс. | Отклонение |
|---|---|---|---|---|
| Стабильный канал | 4.3389 МБ/с | 4.34 | 4.34 | 0.00 |
| Канал, падающий вдвое | 4.3389 МБ/с | 3.02 | 7.70 | 2.47 |

Отсюда минимум, максимум, выборочное стандартное отклонение и коэффициент
вариации. Перцентилей нет сознательно: при десяти замерах `p90`, `p95` и `p99`
совпадают с максимумом, а `statistics.quantiles(method="exclusive")` и вовсе
выдаёт `p95 = 7.97` для выборки, где максимум `7.70` — скорость, которой не
наблюдали.

При одной успешной попытке разброс равен `null`, а не нулю: ноль здесь
неотличим от самого лестного реального ответа — идеально стабильного канала — и
утверждал бы это по одной точке.

## Чего этот замер не показывает

Раздел нужен затем, что интерпретировать число важнее, чем его получить.

**Скорость одного соединения, а не канала.** Браузеры и менеджеры загрузок
качают в несколько потоков и получают больше. Многие серверы и провайдеры режут
скорость **на соединение**, а не суммарно.

**Путь до конкретного сервера.** Медленный результат может означать
перегруженный сервер или плохой маршрут, а не узкий канал. Проверяйте на
нескольких адресах, прежде чем делать вывод о провайдере.

**TCP slow start.** Соединение разгоняется не мгновенно. На файле в пару
мегабайт заметная доля времени уходит на разгон, и замер выходит заниженным.
Поэтому цель должна быть тяжёлой — от десятка мегабайт.

**Кэши.** Программа посылает `Cache-Control: no-cache` и `Pragma: no-cache`,
что защищает от корпоративного прокси, отдающего файл с локального диска. Но
попадание в кэш CDN этим не отменяется и отменяться не должно: это по-прежнему
настоящая передача по сети.

**Момент времени.** Десять запросов занимают секунды. Вечерняя загрузка сети,
дневные лимиты провайдера и соседи по каналу в этот срез не попадают.

## Архитектура

Порты и адаптеры. Зависимости направлены строго внутрь: адаптеры знают о
портах, порты — о домене, домен не знает ни о чём.

```
src/speedmeter/
├── domain.py          неизменяемые результаты и все вычисления над ними
├── exceptions.py      иерархия ошибок
├── ports.py           Downloader, Reporter, ProgressListener — граница
├── runner.py          use case: N последовательных попыток
├── cli.py             разбор аргументов и сборка графа объектов
├── __main__.py        точка входа для python -m
└── adapters/
    ├── http.py        единственный модуль, открывающий сокет
    ├── console.py     человекочитаемый вывод и прогресс
    └── json_report.py машиночитаемый вывод
```

Смысл границы проверяем, а не декларативен. Добавление JSON-вывода — это
[отдельный коммит](https://github.com/firstConsole/speed-test-meter/commits/main),
в котором **два новых файла и ноль правок в существующих**: домен, порты,
runner и консольный адаптер остались нетронутыми. Третий формат обойдётся
ровно в столько же.

Из того же свойства следует тестируемость: `runner.py` проверяется на подставном
`Downloader`, который отдаёт заготовленные исходы по списку. Поэтому тест может
устроить таймаут ровно на четвёртой попытке или прогон, где падает всё — случаи,
которых от настоящего сервера по требованию не добьёшься.

Вычисления живут в `domain.py`, а не в отдельном классе-калькуляторе: иначе
`SpeedReport` превратился бы в мешок полей, чьи значения посчитаны где-то ещё и
могут разойтись с результатами, которые он описывает.

## Разработка

```bash
poetry install

poetry run pytest                   # все тесты
poetry run pytest -m "not network"  # без тех, что открывают сокеты — втрое быстрее
poetry run ruff check .
poetry run ruff format --check .
poetry run mypy src tests
```

176 тестов. Из них одиннадцать — property-based на Hypothesis: они проверяют не
конкретные числа, а инварианты, которые обязаны держаться на любом прогоне.
Например, что агрегатная скорость всегда лежит между минимальной и максимальной
поточечной, и что перестановка попыток ничего не меняет.

Настройки строгие намеренно: `mypy --strict` с `python_version = "3.10"`, чтобы
проверялась самая младшая поддерживаемая версия, и `filterwarnings = ["error"]`
в pytest. Последнее не формальность — именно оно поймало утечку сокета в
адаптере: `urllib` при ответе 4xx/5xx поднимает `HTTPError`, который сам
является объектом ответа с открытым соединением, и отдаёт его наружу
незакрытым.

CI прогоняет линтер и проверку типов один раз, тесты — на Python 3.10, 3.11,
3.12 и 3.13, и отдельно собирает колесо, ставит его в чистое окружение и
запускает установленную команду.
